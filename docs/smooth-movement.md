# Smooth world and player presentation

Enhanced's existing Smooth map setting (also toggled with F6) now controls
both the world catch-up and independent player placement. No new launch option
is required. It works with the opt-in `--responsive-movement` scheduler and with
the standard native command path. Classic retains native presentation.

The window build defaults to 200 ms with a quadratic ease-out: motion starts
immediately and stops gently. The actor's world displacement is interpolated
separately from the camera, so panning no longer drags its bitmap across the
screen. Consecutive steps continue from the currently displayed position.

Replay captures the selected actor's original resources, the terrain below them,
and later foreground writers. Both the ordinary animated-sprite routine and the
party-icon routine are covered. The SDL presenter removes only that actor from
the frozen world layer and draws it separately with the original palette and
nearest-neighbor pixels. Original resource poses/animation frames are retained.
The HUD stays fixed, later terrain occludes the actor, and the native aperture's
elevated spill is preserved at 50–100% zoom in both layouts.

All smoothing is presentation-only. Gameplay coordinates, collision decisions,
turn pacing, clocks and ROM instruction bodies remain unchanged. Pause freezes
the visual travel. Loading, map/room transitions, zoom/layout changes and selecting
a different actor discard stale offsets. Derived actor layers are excluded from
the existing save format and regenerated by the next completed drawing pass.

Validation includes finite/continuous actor travel, resource ownership and
foreground occlusion, load reset, and SDL pixel comparisons: a settled split frame
matches the original composition, and the actor stays fixed during camera-only
travel. Manual Save 3 was checked with the actual ROM and SDL key events.

Actor textures share the full world's source grid, with only their small changed
region uploaded. This preserves the same nearest-neighbor pixel phase at
fractional window scales and avoids a one-pixel shift from cropped textures.

The initial complete suite ran 386 tests (367 passed, 13 skipped, six existing
failures). After aligning texture grids, the 50 relevant camera, actor, zoom,
scene, movement and responsiveness tests had 45 passes and five optional skips; the actor
pixel test also passed with an irregular multi-row sprite pattern.

Final actual-ROM SDL checks used Manual Save 3 in both layouts at 50% and 100%.
Before movement and after the tween settled, disabling/enabling the separate
actor layer produced zero differing RGB bytes in every case. A 33 ms tap made
one step; loading during travel restored the saved coordinates without stale
input; switching to Classic cleared the tween and independent scheduler.
Execution, replay and timing failure counts stayed zero. The final built binary
also loaded the copied save successfully in Enhanced and Classic. The user's
original save and settings were preserved.

Native viewport regression correction: at 100% in the ordinary layout, the
presenter now uses a separate frozen replay of the original 10x10 traversal.
A crop of the expanded map changes the boundary cliffs and lets neighboring
cells overpaint the original silhouettes. Zoomed-out and wide presentation
continue to use the expanded traversal. The player underlay and foreground
ownership are captured from the same selected scene.

Terrain metadata again includes the intrinsic height above its 28x16 footprint.
Native silhouettes that the original renderer admits over the frame are anchored
to the nearest transparent ground point in their column, preserving pixels over
plane B's dithered edge. Signed ground offsets also retain the few native pixels
just below that edge. The same correction applies to the player underlay.

On the copied Manual Save 3, settled 100% native-layout frames match the original
VDP output with zero differing RGB bytes, before and after a movement step,
with smoothing enabled or disabled. SDL2 regression tests cover every 10% zoom
step from 50% to 100%, ground clipping, elevated spill, fixed priority UI,
camera displacement, and exact reset. These tests do not require the optional
font dependency. An actual-ROM resource ABI comparison also checks the native
source-grid clipping against the original translated bitmap writer.

Indoor smoothing uses the same configured presentation tween with the original
10x10 terrain traversal and party icon. Small rooms can keep the camera fixed
while the player moves; scrolling rooms use the original 14/8 pixel camera
projection. Indoor party icons use sprite zero directly, even when the outdoor
actor record has no assigned sprite. Foreground walls retain their ownership.
Native room snapshots publish only after the real bitmap upload, survive
intervening VBlanks, and reset when the room ID changes. Combat keeps its original
presentation. Rooms always use the original 320-pixel layout at 100%; wheel,
middle-click and 0 leave the stored outdoor zoom untouched.

Manual Save 1 was checked with the actual ROM, including walking in a scrolling
room with outdoor wide/50% preferences and a 240 ms test-host tween. Settled frames matched the original
renderer with zero differing RGB bytes; execution, replay and timing failure
counts stayed zero. Indoor SDL regressions cover independently displaced actor
pixels, wall occlusion, pause, scene changes, and restoration of outdoor settings.

The rebuilt executable also loaded Manual Save 1 in Enhanced and Classic.
Both modes ended at identical instruction, cycle, master-clock, frame and game
clock values, with byte-identical native frames and zero replay/timing failures.
The command-line default remains 200 ms for both indoor and outdoor movement;
`--camera-smooth-ms` selects the same duration for both.
